# 🧠 What Is Happening Here?

Inside this line:

```java
OAuth2AuthorizedClient authorizedClient = manager.authorize(authorizeRequest);
```

Spring does this:

1. It reads your `application.yml`
2. Uses:

    * client-id
    * client-secret
    * token-uri
3. Calls Keycloak’s `/token` endpoint
4. Gets a **fresh access token**
5. Returns it to you

So this token is:

```
Generated automatically by your application
NOT the one from Postman
```

If you are still getting `401 Unauthorized`, it means:

* ❌ Wrong audience
* ❌ Wrong client-id

# ✅ Correct Way: Forward the Incoming Token

Instead of generating a new token using:

```java
manager.authorize(authorizeRequest);
```

You should:

1. Read the token from the incoming request
2. Forward that same token to Service-2

---

# 🔥 Updated `fetchData()` (Using Same Token)

Replace your method with this:

```java
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.oauth2.server.resource.authentication.JwtAuthenticationToken;

public String fetchData() {

    // 1️⃣ Get current authentication
    Authentication authentication =
            SecurityContextHolder.getContext().getAuthentication();

    if (!(authentication instanceof JwtAuthenticationToken jwtAuth)) {
        throw new RuntimeException("No JWT token found");
    }

    // 2️⃣ Extract token value
    String accessToken = jwtAuth.getToken().getTokenValue();

    // 3️⃣ Add token to header
    HttpHeaders headers = new HttpHeaders();
    headers.setBearerAuth(accessToken);

    // 4️⃣ Call Service-2 with SAME token
    var response = rest.exchange(
            service2Url + "/data",
            HttpMethod.GET,
            new HttpEntity<>(headers),
            String.class
    );

    return response.getBody();
}
```

# 🧠 What Happens Now?

Flow becomes:

```
Postman → Service-1 (with token)
Service-1 forwards SAME token → Service-2
Service-2 validates token
```

No new token generated.
No client_credentials flow.
Pure token forwarding.

---

# ⚠️ Important

For this to work:

### 1️⃣ `/proxy` must require authentication

Change this back:

```java
.authorizeHttpRequests(auth -> auth
        .anyRequest().authenticated()
)
```

NOT:

```java
.requestMatchers("/proxy").permitAll()
```

Because if `/proxy` is permitAll → no authentication → no token in SecurityContext → will fail.

# 🎯 When To Use Which?

## 🔹 Generate New Token (Client Credentials)

Used for:

* Machine to machine
* Internal service communication
* No user involved

---

## 🔹 Forward Same Token (Token Relay Pattern)

Used for:

* API Gateway
* User-based requests
* Microservice chaining
